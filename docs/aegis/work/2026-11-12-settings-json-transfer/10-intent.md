# 设置导入导出（JSON）- Intent

日期：2026-11-12。工作区 `main`（在 `944a93d` 之上，含此前未提交的 i18n 改动）。

## 目标

服务端提供「把当前设置项导入导出为 JSON」的能力，供管理员备份、迁移与复制部署：

- `GET /api/v1/admin/settings/export`：导出当前可配置项的一份 JSON。
- `POST /api/v1/admin/settings/import`：用同一份 JSON 整份还原配置。

## 范围

覆盖管理端真正可配置的四类设置：

1. GitHub 代理模板（`github_proxy_template`）
2. GitHub 源检查更新窗口（`github_sync_max_age`）
3. 标签目录（`tag_catalog`，含中英显示名与描述）
4. 下载节点清单（`download_nodes`，含节点类型、权重、能力、Cloudreve 目录等）

不在范围：模组/版本/投稿等目录数据、用户与角色授予、审核与设置审计历史、应用资产与镜像状态。这些不是「设置项」，且体量与一致性要求完全不同（导出归档属于另一个能力）。

## 非目标

- 不做前端按钮与文件选择器（本切片只做服务端契约与实现）。→ 该非目标随后被同一工作记录的第二切片覆盖：管理页「备份与迁移」卡片已补齐，见 `90-evidence.md`。
- 不做跨版本文档迁移：文档自带 `format` / `version`，版本不符直接拒绝。
- 不在导出里携带任何凭据（GitHub 令牌、节点密码）。

## 关键约束

- **导出永不含秘密**：与 `GET /admin/settings`、`GET /admin/download-nodes` 现有口径一致；导出文件允许被复制到工单、聊天与备份目录。
- **导出的文件必须能直接导回**：因此节点密码缺失时按 `id` 沿用本部署已存的密文，令牌在文档里缺席时保持现状。
- **导入是整份替换而不是补丁**：只有 `download_nodes` 用「字段缺席」表示不动，其余字段缺席即等于置空/恢复默认。
- **不静默丢弃**：部署用 `GITHUB_SYNC_MAX_AGE` 钉死窗口时，导入返回 409，而不是假装成功。
- **一次写入、失败整份回滚**：设置、节点、被清理的模组标签与审计事件不能出现半套状态。
- 记录一次设置审计（谁、何时、令牌是否变、标签是否变、清理了多少模组标签）。

## 验收

- 单测覆盖：导出形状与不泄密、权限与 CSRF/同源、往返幂等、新部署带凭据还原、`download_nodes` 缺席/空数组语义、标签清理与审计、写盘失败回滚、各类非法文档的稳定错误码。
- `go test ./...` 全绿。
- 契约文档（`docs/frontend-contract.md`）与运维文档（`docs/operations.md`）同步描述新端点。
