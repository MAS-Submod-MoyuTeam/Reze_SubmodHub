# 目录页刷新的常驻入口

## 结论

目录页的「刷新」以前只写在列表表头的一行小字里，且只在有数据时出现：目录一旦加载失败就只剩失败条里的重试按钮，没有常驻入口。现在刷新是右下角常驻的圆形悬浮按钮，语义与桌面客户端一致。

## 两条既有缺陷

1. **失败态在「有旧数据」时永远看不到。** `reloadCatalog` 失败时保留上一次成功的数据，`catalogLoading` 一结束就重新渲染骨架；失败一直只体现在 Toast 里，页面级的失败条与重试入口永远轮不到渲染。
2. **失败态在「没有数据」时会自己消失。** 骨架消失后目录还是空的，空态与失败态叠在同一块区域里，读屏与截图都无法分清「读不到」和「筛不到」。

## 现在的行为

- 首次加载（手上没有任何数据）仍显示骨架；之后每一次拉取都是刷新：列表留在屏幕上，悬浮按钮置灰并旋转直到拉取结束。
- 失败时保留旧数据，失败条挂在列表上方并给出唯一的「重新加载目录」；此时悬浮刷新隐藏，避免两个入口并排。
- 失败条在场时不渲染空态。
- 并发点击共享同一次拉取，不会把同一份目录请求打两遍。

## 未做

- 列表表头原有的「刷新」文字按钮保留：它是现在唯一的文字刷新入口，键盘与读屏都能直接找到。两个入口调用同一个动作，且同时被置灰。
