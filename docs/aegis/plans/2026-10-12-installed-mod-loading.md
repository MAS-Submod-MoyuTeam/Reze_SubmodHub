# 已安装模组加载动画实施计划

日期：2026-10-12  
状态：已实施完成  

## 1. 目标与范围

桌面端“已安装模组”首次读取或切换 MAS 实例时展示加载动画，避免扫描尚未结束就误显示“暂无模组”。同实例刷新保留列表，并提示正在刷新。

覆盖已托管模组、未托管模组与精灵包三个子标签。不改 Android、Web 演示端、Go 扫描接口，以及安装、卸载、收养和优先级规则。

- 切换 MAS 实例：重新读取，展示骨架，不显示上一实例的数据。
- 切换页面或子标签：请求未完成时显示动画；数据已就绪时直接显示，不强制重新扫描或制造等待。

## 2. 当前基线

实施前复核入口，不依赖固定行号：

- `clients/desktop/src/App.tsx`：`scanLocalSubmods` 并行调用 `ScanLocalSubmods` 和 `ListInstalledArchives`，合并托管与未托管结果，目前没有独立扫描加载状态。
- `clients/desktop/src/App.tsx`：`syncInstances` 清空列表并触发扫描；精灵包刷新和删除后重读还有直接扫描调用。
- `clients/desktop/src/components/InstalledView.tsx`：空状态依赖列表长度，没有扫描状态输入。
- `clients/desktop/src/index.css`：样式入口，优先复用现有 Tailwind 工具类及图标动画。
- `clients/desktop/src/installedFiles.test.ts`：既有测试示例，新测试沿用现有工具。
- `clients/desktop/package.json`：提供 `lint`（TypeScript 检查）和 `build`，没有统一 `test` 脚本。

已确认前端没有区分“加载中”和“成功为空”。实施时还需核实原生扫描是否依赖全局当前实例；前端忽略旧响应不能保证原生请求内部的实例隔离。

## 3. 推荐交互

采用“首次加载骨架屏 + 同实例刷新保留内容”，不使用全页遮罩。

| 场景 | 展示 |
| --- | --- |
| 首次读取有效实例 | 骨架卡片及“正在读取已安装模组…” |
| 切换 MAS 实例 | 清除旧实例内容，显示骨架，保留标题及标签导航 |
| 同实例刷新 | 保留已有列表，显示旋转图标和“正在刷新…” |
| 首次精灵包读取 | 精灵包区域骨架及“正在读取精灵包…” |
| 成功且为空 | 停止动画，显示现有空状态 |
| 首次读取失败 | 错误提示及重试，不显示成功空状态 |
| 有数据时刷新失败 | 保留旧结果，注明数据未更新并提供重试 |
| 无有效实例 | 提示选择实例或配置目录，不进入无限加载 |

尚无可靠结果时，数量显示占位符，不显示误导性的零。同实例刷新保留上次数量。加载期间禁用依赖扫描结果的操作；失败后保留的旧列表不自动恢复危险操作。

不设置强制最短等待时间。遵循减少动态效果设置，静态占位和文字仍表达加载状态；列表提供 `aria-busy` 及可读状态提示。

## 4. 状态与请求约束

模组和精灵包分别维护 `idle / loading / success / error`，关联实例标识、请求序号和错误信息。

- `idle` 表示尚未读取，不等价于成功空列表。
- 请求开始前记录实例及递增序号，完成时同时校验。
- 过期请求不得提交数据、错误提示，也不得结束较新请求的加载状态。
- 当前请求成功后更新结果，失败进入错误状态并停止动画。
- 同实例、同数据源的重复刷新合并或忽略。
- 切换实例立即使旧请求失效；无有效实例时清理状态，不扫描。
- 模组与精灵包独立结束加载，一方失败不阻塞另一方。
- 若原生扫描依赖全局实例且无法可靠隔离，需要序列化切换与扫描，不能仅做前端响应过滤。

## 6. 实施步骤

### 任务一：核实入口并补充失败测试

1. 检查初始化、实例切换、安装后刷新、精灵包刷新和删除后重读入口。
2. 核实原生扫描实例语义及实际测试命令。
3. 添加延迟响应测试：返回前处于加载状态，不显示成功空状态。
4. 添加 A 实例慢请求、B 实例快请求的竞态测试。

验证：新增测试在实现前按预期失败，既有测试不作无关修改。

### 任务二：统一扫描生命周期

1. 为模组和精灵包接入独立状态。
2. 将直接精灵包扫描收敛到统一刷新函数，包括删除后重读。
3. 接入实例与请求序号校验，区分首次读取与同实例刷新。
4. 处理无实例、失败及重复刷新，避免永久加载或旧请求清理新状态。

验证：状态与竞态测试通过，原有结果映射及接口保持兼容。

### 任务三：接入加载展示

1. 给 InstalledView 增加状态、错误信息及重试回调。
2. 保留标题和标签栏，在内容区展示骨架及加载文字。
3. 刷新保留内容，按钮旋转并防止重复触发。
4. 空状态仅用于成功空结果，失败展示错误与重试。
5. 禁用依赖扫描结果的操作，保持标签导航可用。
6. 接入可访问提示及减少动态效果支持。

验证：加载、空结果和失败互斥；精灵包状态不影响模组标签；键盘导航可用。

### 任务四：回归与验收

1. 按核实的命令运行新增及相关既有测试，不假设存在 `npm test`。
2. 执行 `npm --prefix clients/desktop run lint`。
3. 执行 `npm --prefix clients/desktop run build`。
4. 实际桌面客户端验证首次进入、切换实例、子标签切换、刷新与失败重试。
5. 用可控延迟验证慢响应、快速切换和减少动态效果设置。

记录实际命令及结果。浏览器模拟不能替代原生实例语义验证；既存失败单独记录，不扩展修复范围。

## 7. 验收标准

- 首次扫描结束前不显示“暂无模组”或误导性的零数量。
- 切换实例不展示旧实例数据，旧响应不覆盖新状态。
- 托管与未托管共用扫描状态，精灵包独立加载。
- 已就绪标签直接显示，进行中的扫描有明确提示。
- 同实例刷新保留列表，重复点击不重复扫描。
- 失败和成功空结果明确区分，动画停止且能够重试。
- 不通过旧列表触发针对错误实例的操作。
- 安装、卸载、收养、优先级和文件清单查询行为不变。
- 新增测试、类型检查、构建及实际客户端交互验证完成。

## 8. 清理与回退

保留数据 DTO、原生接口及业务入口。统一刷新后删除被替代的直接扫描调用，避免新旧生命周期并存；现有空状态仅用于成功空结果。

本功能不迁移磁盘数据或修改 manifest。回退撤销前端加载协调及展示改动即可；若需修改原生接口，先更新计划并单独确认范围。
